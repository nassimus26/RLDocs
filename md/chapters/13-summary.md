# Chapter 13: Summary

Reinforcement learning produces **good trajectories** when labeled correct actions are not available. The agent sees a state, chooses an action, and receives a scalar reward that may arrive much later than the choice that caused it. Supervised learning would need the correct action at each step; here that label is missing, and the only signal is the delayed number. A **policy** $\pi$ is the rule for choosing an action in a state. The goal is to find a $\pi$ that makes the long-run return large.

Chapters 1–3 write the interaction as an MDP: at each step the agent sees a state $s$, picks an action $a$, and the environment answers with a next state $s'$ and a reward $r$. The dynamics $P(s',r\mid s,a)$ are the probability of that pair $(s',r)$ given $(s,a)$. The quality of a trajectory from time $t$ is the **return** $G_t=\sum_{k=0}^\infty\gamma^k R_{t+k+1}$: it adds every future reward, with a reward $k$ steps ahead scaled by $\gamma^k$ so later rewards count less than earlier ones. The value functions $V^\pi$ and $Q^\pi$ are the expected return from a state, or from a state–action pair, if the agent keeps following a fixed $\pi$. Listing every possible future under $\pi$ and $P$ is not practical. Bellman rewrites the same expectation as one immediate reward plus a discounted copy of the value at the next state, so a value depends only on the next step. If the backup averages over actions according to $\pi$, the result is $V^\pi$ or $Q^\pi$: a score for that $\pi$, with $\pi$ held fixed. If the backup takes $\max_a$ instead of $\pi$, it is the optimality backup; repeating it is what **improves** $\pi$. When $P$ is known, dynamic programming carries out that improvement: value iteration repeats the optimality backup and then reads a greedy $\pi$; policy iteration alternates full evaluation of the current $\pi$ with a greedy improvement, until the policy stops changing.

Chapters 4–6 keep those same Bellman backups but no longer use $P(s',r\mid s,a)$. The agent only sees samples $(S_t,A_t,R_{t+1},S_{t+1})$ from interaction. Monte Carlo waits until the episode ends and uses the finished return $G_t$ as the target for $V(S_t)$ (or $Q(S_t,A_t)$). TD does not wait: TD(0) steps $V(S_t)\leftarrow V(S_t)+\alpha\bigl[R_{t+1}+\gamma V(S_{t+1})-V(S_t)\bigr]$, so the target is the one-step backup $R_{t+1}+\gamma V(S_{t+1})$ with the current table in place of $V^\pi$. For control the table is $Q$. Chapter 6 introduces two one-step methods on that table. SARSA puts the **next action from $\pi$** in the backup, $R_{t+1}+\gamma Q(S_{t+1},A_{t+1})$ with $A_{t+1}\sim\pi(\cdot\mid S_{t+1})$, and therefore estimates $Q^\pi$ (on-policy). **Q-learning** puts $\max_{a'}Q(S_{t+1},a')$ in the backup even if $\pi$ would have chosen a different $A_{t+1}$, and therefore estimates $Q^*$ (off-policy). In both cases $\pi$ is typically $\varepsilon$-greedy in the current $Q$, so the agent still tries actions it is not yet sure about; that is exploration.

Chapters 7–10 replace the table $Q(s,a)$ by an approximator $\hat{Q}(s,a;\theta)$ (or $\hat{V}(s;\mathbf{w})$). Only a weight vector is stored, not one number per pair. The TD backups keep the same shape: SARSA still uses $A_{t+1}\sim\pi$, Q-learning still uses $\max_{a'}\hat{Q}$. In the table, changing $Q(s,a)$ changes only that cell. Because $\theta$ is shared, changing $\theta$ after one pair also changes $\hat{Q}$ at other pairs that use those weights. Q-learning with $\hat{Q}$ therefore has all three: shared $\theta$, a bootstrap $R+\gamma\max_{a'}\hat{Q}(s',a')$ that depends on the current weights, and the off-policy $\max$ from Chapter 6. That combination is the **deadly triad**: $\theta$ can grow without bound. The tabular Q-learning of Chapter 6 uses the same $\max$ backup but changes only one cell, so it does not have this failure. DQN is off-policy $\hat{Q}$ with two fixes: a replay buffer $\mathcal{D}$ of $(s,a,r,s',d)$ so updates are not only the newest transition, and a frozen copy $\theta^-$ in the bootstrap $y=r+\gamma(1-d)\max_{a'}\hat{Q}(s',a';\theta^-)$, so the target does not move every time $\theta$ does. Double DQN splits that $\max$: $\theta$ chooses $a^*=\arg\max_{a'}\hat{Q}(s',a';\theta)$, and $\theta^-$ supplies the value $\hat{Q}(s',a^*;\theta^-)$. Policy gradients skip learning $\hat{Q}$ as the object of control and instead step $\theta$ of $\pi_\theta(a\mid s)$ by $\nabla_\theta J(\theta)=\mathbb{E}\bigl[\sum_t\nabla_\theta\log\pi_\theta(A_t\mid S_t)\,A(S_t,A_t)\bigr]$. REINFORCE takes $A\leftarrow G_t$ (Monte Carlo). Actor–critic takes $A$ from a learned $\hat{V}$ or $\hat{Q}$ (TD-style), which is the same MC-versus-bootstrap split as Chapters 4–6, now on $\pi_\theta$ instead of on a $Q$-table.

Chapter 11 introduces **reinforcement learning from human feedback (RLHF)**. It puts that same $\pi_\theta$ on language: a prompt $x$ is $S_0$; a reply $y=(y_1,\ldots,y_T)$ is the trajectory, each token an action. The next state appends that token, so $P(S_{t+1}\mid S_t,A_t)=1$. The probability of a full reply is $\pi_\theta(y\mid x)=\prod_{t=0}^{T-1}\pi_\theta(y_{t+1}\mid x,y_1,\ldots,y_t)$. There is no environment reward after each token, so the scalar that Chapter 9 would have called $R_{t+1}$ is missing. Humans compare two full replies: a winner $y_w$ and a loser $y_l$. Those triples train a reward model $r_\phi$ by $L(\phi)=-\sum\log\sigma\bigl(r_\phi(x,y_w)-r_\phi(x,y_l)\bigr)$. The policy loop then samples $y\sim\pi_\theta(\cdot\mid x)$ and scores it. A frozen copy $\pi_{\mathrm{ref}}$ of the start of the RL stage enters the score as $R_\theta(x,y)=r_\phi(x,y)-\beta\log\bigl(\pi_\theta(y\mid x)/\pi_{\mathrm{ref}}(y\mid x)\bigr)$, so raising $r_\phi$ cannot pull $\pi_\theta$ arbitrarily far from the reference. The policy is stepped by $\nabla_\theta J(\theta)=\mathbb{E}\bigl[R_\theta(x,y)\,\nabla_\theta\log\pi_\theta(y\mid x)\bigr]$, the same score $\nabla_\theta\log\pi_\theta$ as Chapter 9, with $R_\theta$ in place of the return $G_t$. PPO reuses a batch from $\pi_{\theta_{\mathrm{old}}}$: the importance ratio is $\rho=\pi_\theta(y\mid x)/\pi_{\theta_{\mathrm{old}}}(y\mid x)$, and the clip in $L^{\mathrm{PPO}}$ stops inner-loop steps from driving $\rho$ far from $1$.

Chapter 12 introduces **InstructGPT** and **DeepSeek-R1-style** training. It derives the supervised fine-tuning that produces Chapter 11’s $\pi_\theta$ and $\pi_{\mathrm{ref}}$, and, when a program can check $y$, replaces $r_\phi$ by a rule. SFT starts from a pretrained $\pi_{\mathrm{base}}$ and a fixed set $\mathcal{D}_{\mathrm{SFT}}$ of gold pairs. Teacher forcing raises $\pi_\theta(y\mid x)$ on those strings with no sampler: $L_{\mathrm{SFT}}(\theta)=-\frac1N\sum_n\log\pi_\theta\bigl(y^{(n)}\mid x^{(n)}\bigr)$, then $\theta\leftarrow\theta-\alpha\nabla_\theta L_{\mathrm{SFT}}$. InstructGPT is that SFT, then $r_\phi$, then PPO; the SFT weights initialize $\pi_\theta$ and are frozen as $\pi_{\mathrm{ref}}$. When a program can check $y$, $r_\phi$ is not needed. The rule score is $r(x,y)=r_{\mathrm{acc}}(x,y)+r_{\mathrm{format}}(y)$. GRPO samples a group $y^{(1)},\ldots,y^{(G)}\sim\pi_{\theta_{\mathrm{old}}}(\cdot\mid x)$, sets $A_i=\bigl(r_i-\mathrm{mean}(r)\bigr)/\bigl(\mathrm{std}(r)+\delta\bigr)$, and minimizes $L_{\mathrm{GRPO}}=L_{\mathrm{clip}}+\beta\,\mathrm{KL}(\pi_\theta\|\pi_{\mathrm{ref}})$. The KL stays in the loss, not inside $r$, so the group mean and std do not mix drift with the rule. Reject-then-SFT keeps only replies with $f=1$ (both rule terms $1$), sets $\pi_\theta\leftarrow\pi_{\mathrm{base}}$, and runs SFT on the keepers. Distillation is that same SFT on a smaller student from the student’s own $\pi_{\mathrm{base}}$; DeepSeek-R1 reuses the already-kept traces rather than filtering again.
